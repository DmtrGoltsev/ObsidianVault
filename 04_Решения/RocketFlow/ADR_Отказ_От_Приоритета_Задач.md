# ADR: Отказ от приоритета задач

## Решение

Пользовательский приоритет задачи и изменение приоритета удалены из UI и бизнес-логики RocketFlow. Сортировка, validation, переносы и настройки не используют приоритет.

Технический приоритет доставки FCM/Android `HIGH` не относится к этому решению и остаётся транспортной настройкой уведомлений.

## Совместимость

До отдельного завершения поддержки production V20 и старых APK поле `priority` сохраняется как непрозрачная compatibility shadow:

- новая задача получает каноническое значение `5`;
- обновление существующей задачи сохраняет её историческое shadow-значение;
- старые wire-поля и DB-колонки временно остаются;
- migration V21 меняет только metadata defaults, без массового `UPDATE`, удаления данных или `DROP`;
- legacy decay settings отключены и не имеют продуктового эффекта.

Удаление полей/колонок и client preservation code является отдельным breaking change после явного закрытия rollback V20 и поддержки старых APK.

## Сортировка

Детерминированный порядок не зависит от priority: плановые/предельные даты по контракту конкретного списка, затем `createdAt`, затем `id`. Backend сравнивает UUID в unsigned-порядке, совпадающем с PostgreSQL `uuid ASC`.

## Production boundary

Решение реализовано в кандидате V21, но не развёрнуто. Production остаётся на Flyway V20 и source `910c061de4af9395d9bb682624bd966b2977a738` до отдельного подтверждённого rollout.
