## Текущая production-архитектура

```text
Android
  ├─ HTTP /v1/* ──> публичный фильтрующий прокси ──> Gateway ──> Task Core ──> PostgreSQL
  └─ FCM-сигнал <── Task Core push publisher <────── outbox

Задача агенту
Android ──> Task Core ──> task-run relay ──> OpenClaw
                                      └────> n8n ──> Action Executor ──> Task Core
```

FCM не передаёт текст задачи, результат агента, токен или другой чувствительный контент. Сигнал содержит технические идентификаторы и версию; после получения Android делает HTTP-синхронизацию. WebSocket в текущем рабочем пути отсутствует.

Мобильный production origin: `http://154.59.110.121/`. Публично разрешены только health-маршруты и белый список `/v1/*`; внутренние и административные маршруты не публикуются. Это осознанный MVP-компромисс: пользователь принял риск незашифрованного HTTP. Аутентификация API, ротация сессии, PIN/биометрия и шифрование локальных данных сохраняются, но они не защищают сетевой трафик от пассивного перехвата.

## Что умеет мобильное приложение

- принять приглашение, создать локальный PIN и использовать системную биометрию;
- хранить сессию и данные локально, автоматически обновлять API-сеанс;
- создавать задачи офлайн, менять статус, добавлять результат и отменять;
- редактировать заголовок, описание, срок и видимость задачи; nullable-поля сохраняют различие между отсутствующим значением, очисткой и новым значением;
- синхронизировать зависимые офлайн-действия по фазам после получения серверного UUID;
- показывать фильтры задач; кнопка `+ Задача` остаётся доступной после создания первой задачи;
- управлять фокусом, открывать календарь, входящие, approvals и дерево документов;
- отправлять текстовую команду агенту, отображать статусы и сохранять историю после перезапуска;
- зарегистрировать FCM-токен и получать нейтральные уведомления на совместимом устройстве с актуальным Google Play services;
- после нажатия на уведомление пройти PIN/биометрию и открыть точную задачу либо диалог.

Сроки задач и календарь отображаются в фиксированной продуктовой зоне `Europe/Moscow`; серверное RFC3339-значение хранится без изменения.

## Что умеет backend и агент

- Gateway выдаёт и обновляет API-сессии, применяет authentication и пропускает только разрешённые мобильные маршруты;
- Task Core хранит задачи, версии, фокус, календарь, назначения, предложения, approvals, документы, входящие, запуски агента, аудит и outbox;
- outbox обеспечивает устойчивую публикацию событий, дедупликацию доставок, повторные попытки и DLQ;
- FCM publisher отправляет сигналы по изменениям задач, запусков агента, входящих и approvals;
- relay переводит `QUEUED`-запуски агента в OpenClaw и возвращает результат в Task Core;
- OpenClaw отвечает через модель DeepSeek и имеет строго ограниченный allowlist инструментов; у каждого агентного запуска есть изолированная защита от повторных инструментальных действий после детерминированной ошибки;
- n8n маршрутизирует типизированные намерения, а Action Executor подписывает и выполняет разрешённые действия с идемпотентностью и аудитом.

Полный список инструментов и процедура добавления нового инструмента описаны в [интеграционном документе](../../../ChatGPT/Агенты/N8NAgents/docs/PORUCHIK_INTEGRATION.md).
