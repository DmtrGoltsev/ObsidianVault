# Решение: OpenClaw ведёт диалог, n8n выполняет действия

## Состояние решения

Решение утверждено для MVP. Фактическое внедрение считается завершённым только после проверки на рабочем сервере.

## Контекст

Проекту нужен помощник, который понимает свободную речь и помнит контекст. Одновременно действия с задачами, внешними службами и данными должны быть предсказуемыми, проверяемыми и защищёнными от повторов.

## Решение

- OpenClaw отвечает за разговор, контекст и выбор разрешённой возможности.
- n8n отвечает за права, обязательные правила, подтверждения, интеграции и аудит.
- PostgreSQL хранит надёжное состояние операций.
- Markdown хранит смысловую память.
- Между OpenClaw и n8n используется закрытый интерфейс с подписанными структурированными командами.

## Почему не только OpenClaw

Языковая модель может неоднозначно понять текст. Ей нельзя напрямую доверять операции с последствиями, выбор получателя, учётных данных или адресов запросов.

## Почему не только n8n

n8n хорошо выполняет строгие сценарии, но неудобен как постоянно работающий собеседник со свободным контекстом и расширяемой памятью.

## Последствия

Положительные:

- гибкий разговор не ослабляет контроль действий;
- новые инструменты можно добавлять по одному;
- правила и аудит остаются централизованными;
- OpenClaw можно остановить без потери задач в PostgreSQL.

Отрицательные:

- появляется дополнительный постоянно работающий компонент;
- требуется поддерживать строгий договор между OpenClaw и n8n;
- при изменении инструмента нужны проверки обеих сторон.

## Условие пересмотра

Решение пересматривается, если ограниченный сервер не выдерживает OpenClaw, закрытый интерфейс не обеспечивает нужную надёжность или появится более простой способ сохранить те же границы безопасности.
