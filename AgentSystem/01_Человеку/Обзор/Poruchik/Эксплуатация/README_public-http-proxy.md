# Внешний HTTP-прокси Poruchik

Исходник восстановлен из действующего ELF Go1.25.1 и проверен сравнением поведения двух исполняемых файлов. Исторический исходник не найден; это контролируемая реконструкция. Единственное намеренное изменение DEF032 — ответ429 в формате JSON Problem с `code=RATE_LIMITED` и новым `traceId`, совпадающим с `X-Correlation-Id` ответа.

Действующий до исправления файл: `/usr/local/libexec/poruchik-public-http-proxy`, SHA256 `f6b0a764ec2b7bdabb433390482eac4a23e865b2af4d5e1015d7a6d233d1eea9`.

## Сохранённое поведение

- Вход `:80`, upstream `http://127.0.0.1:18791`, стандартный `httputil.NewSingleHostReverseProxy` и `DefaultTransport` Go1.25.1.
- Проверяется `URL.Path`: пустой путь, `..` или `//` запрещены. Допускаются GET `/health/live`, GET `/health/ready` и непустой `/v1/*`. Более узкая проверка публичных методов и маршрутов остаётся в Gateway. `RawQuery` и экранирование пути передаются штатным ReverseProxy.
- Порядок: проверка `RemoteAddr` → пути → заявленного `ContentLength` → лимита → пересылка. `ContentLength > 1048576` даёт413; это прежняя проверка заявленного размера, не новое ограничение потокового тела.
- Лимит60 принятых запросов на IP за скользящие60сек. Хранятся временные метки, возрастом строго меньше минуты; отклонённый запрос не добавляется. Ключ — IP из `RemoteAddr`, не входной `X-Forwarded-For`.
- Входной `X-Forwarded-For` заменяется IP соединения; стандартный ReverseProxy затем добавляет тот же IP. Этот исторический дубль сохранён. `X-Forwarded-Proto=http`.
- Таймауты чтения заголовка/чтения/записи/простоя:5/20/30/60сек; `MaxHeaderBytes=8192`.
- Прочие ответы сохранены:400 `bad request`,404 `404 page not found`,413 `request too large`,502 `gateway unavailable`.

## Сборка и проверка

Сборка из этой директории использует Go1.25.1 и прежние настройки без модуля, чтобы сохранить стандартные совместимые настройки Go исходного артефакта:

```sh
GO111MODULE=off GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -o poruchik-public-http-proxy main.go
GO111MODULE=off go test -run 'TestSlidingLimit|TestRateProblem' -count=1
```

Две независимые сборки кандидата дали SHA256 `71b15b10c755a6db75f87774e31fc6551cb588632904ce9e97116284879846d9`.

`TestBinaryDifferential` исполняет сохранённый оригинал и кандидат последовательно в изолированном Linux-контейнере. Внутренний тестовый HTTP-сервер принимает только loopback-запросы; сети production нет.21 сценарий у каждого файла совпал по статусу, типу и телу ответа, кроме намеренного изменения429. Проверены пути и query, методы, граница тела, доверенные заголовки, конкурентная пара на границе60, отдельный IP и отсутствие обхода через поддельный заголовок. Константы таймаутов сверены с инструкциями исходного ELF; длительные таймауты отдельным ожиданием не проверялись.

Доказательства прогона `MVP0-QA-20260910-TOOLS-1ebebe44`: `def032-execution.json` содержит команду Docker, точный образ и хеши входов/выходов; `def032-comparison.json` — результаты21 сценария. Исходные API-проверки NET01/02 и исправления query переиспользуются.

## Выпуск

Перед заменой обязательны совпадение хешей текущего файла и unit, резервная копия обоих и ревью конкретного скрипта выпуска. При ошибке после замены восстанавливается только этот бинарник, затем проверяются хеш, активность сервиса и readiness через порт80. Конфигурация Gateway, квоты и другие сервисы не меняются. Отдельный искусственный откат исправного production не требуется.

Это исправление не доказывает точную границу120 запросов Gateway на principal: внешний лимит60/IP может сработать раньше.
