## Известные ограничения и риски

### P2 — новый диалог после force-stop

Если совершенно новый диалог создан, пока приложение force-stopped, после ручного запуска он не выбирается автоматически без нажатия на сохранённое уведомление. Известный диалог восстанавливается через HTTP. Потери серверных данных нет.

Явный force-stop через настройки Android или `adb` также запрещает приложению получать FCM до следующего ручного запуска. Это системное ограничение Android, а не дефект push-first. Уведомления без входа в приложение подтверждены для обычного фонового состояния и остановленного процесса без force-stop.

### Неполное редактирование задачи

Полный mobile/backend contract редактирования title, description, due и visibility не завершён. Поддержанные действия status/result/cancel работают.

### Direct HTTP

Мобильный трафик не шифруется. Аутентификация не устраняет возможность пассивного перехвата. Это осознанное решение владельца для быстрого личного MVP; HTTPS остаётся приоритетным усилением.

### Два локальных снимка

`C:\Users\style\Documents\Codex\Poruchik` соответствует релизному коду. `C:\Users\style\Documents\ChatGPT\Агенты\poruchik-pushfix-src` отстаёт и не должен использоваться для сборки.
