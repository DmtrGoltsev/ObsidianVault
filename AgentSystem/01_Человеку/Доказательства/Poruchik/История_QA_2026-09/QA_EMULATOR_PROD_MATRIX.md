# Объединённая матрица: эмулятор и production backend

Статус: объединение независимых каталогов QA-лидов 1, 2 и 3 и текущий отчёт исполнения. Исходные каталоги сохранены. Статус PASS присваивается только после привязки актуального доказательства к точному артефакту и тестовому контуру; частичные результаты перечислены в QA_EXECUTION_20260910.md и не закрывают составной кейс.

Цель — ноль открытых дефектов в согласованной матрице после исполнения. Это не утверждение об отсутствии всех возможных ошибок вне матрицы.

## Нормализация и критика источников

- Базой подробных UI/user-journey кейсов принят L1. Совпадающие требования L2/L3 объединены на уровне перехода и oracle.
- L2 добавил важные AVD, Doze/WorkManager, requestId, upgrade и rapid-double-action границы. Его compound cases разделяются в дополнениях. Cleanup по префиксу заменён на exact UUID ledger.
- L3 добавил прямой API/tool/scheduler/operations слой. WORKSPACE нормализовано в фактическую visibility TEAM; pagination для GET /v1/tasks не включена, потому что её нет в актуальном контракте.
- 13 poruchik_* и 5 reminder_* инструментов требуют отдельных результатов; групповой PASS не закрывает пропущенный tool.
- Старые PASS автоматически не переносятся. UI oracle не заменяет Room/API/DB/audit/outbox oracle для stateful кейсов.
