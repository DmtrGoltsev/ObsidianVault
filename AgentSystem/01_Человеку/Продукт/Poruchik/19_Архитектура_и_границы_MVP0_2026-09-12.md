# Poruchik — архитектура и границы MVP0

Эта заметка описывает устойчивую архитектуру; статусы выпуска и QA определяет только [[18_Сводка_приёмки_MVP0_2026-09-12]]. Исходный документ `ARCHITECTURE.md` от 7 сентября не использовать как источник текущих версий, хешей или результатов release.

Android-клиент хранит локальную рабочую модель и последовательную offline-очередь в Room. Операции применяются к серверу последовательно; подтверждённые результаты и идемпотентность предотвращают повторный эффект при повторе. Серверное ядро задач — источник истины для задач, прав, событий и результатов; клиентское состояние не заменяет серверные полномочия.

Исходный код опубликован отдельным приватным снимком [AgentSystem](https://github.com/DmtrGoltsev/AgentSystem), ветка `main`, commit `703e49a2dc5f983ec5bfb6413c01d75f44774859`. В снимке отдельно сохранены `Poruchik/` и `N8NAgents/`; действующие локальные исходники остаются в `C:/Users/style/Documents/Codex/Poruchik` и `C:/Users/style/Documents/ChatGPT/Агенты/N8NAgents`. Снимок не синхронизируется автоматически, поэтому дальнейшие изменения требуют явной синхронизации и не должны вестись в расходящихся копиях.

Текущий путь мобильного API: Android → публичный proxy с allowlist (разрешённый список маршрутов) → Gateway → Task Core → PostgreSQL. Активный `/v1/*` использует прямой HTTP; конфиденциальность транспорта не заявляется и это принятый риск MVP0. Виртуальная частная сеть, WebSocket и постоянный SSH-туннель не являются активным путём API. SSH используется только для одноразового приглашения и операторского доступа. Внутренние сервисы, административные маршруты и n8n не публикуются.

Путь действий агента: OpenClaw понимает запрос и контекст → n8n применяет правила процесса → Action Executor выполняет разрешённый типизированный инструмент → Task Core принимает решение и фиксирует эффект. Telegram и Android имеют общую долговременную модель задач, но отдельные текущие диалоги. Агент не получает неограниченный доступ к базе, shell или произвольным HTTP-вызовам.

Для мобильного приложения FCM — основной путь уведомлений, HTTP — авторитетный путь восстановления состояния после ручного запуска. После явного Android force-stop FCM может быть подавлен системой до ручного запуска; это системное ограничение, а не потеря серверного состояния. Уведомления не должны содержать приватный текст задач или результаты.

Граница сети исключает публичный доступ к внутренним сервисам; права пользователя, сессия и объектные проверки остаются обязательными независимо от маршрута. Секреты, ключи, PIN и идентификаторы приглашений не документируются.
