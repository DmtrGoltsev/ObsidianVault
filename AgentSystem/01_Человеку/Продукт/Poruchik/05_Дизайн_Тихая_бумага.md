# Poruchik — дизайн «Тихая бумага»

Статус макетов: концепция для обсуждения, не окончательная спецификация интерфейса.

## Идея

Интерфейс Poruchik должен напоминать спокойный рабочий блокнот: крупный текст, много воздуха, простые карточки и одна очевидная операция на экране. Визуальная простота наследует сильную сторону RocketFlow, но компоновка и компоненты создаются заново.

## Палитра

- фон: `#F8F4EC`;
- поверхность карточек: `#FFFDF7`;
- основной текст: `#20201D`;
- лесной зелёный: `#2F6B57`;
- разделители: `#D9D0C1`;
- янтарный: только для ожидающего решения;
- приглушённый красный: только для отмены и ошибки.

## Правила

- одна главная операция на экране;
- область нажатия не менее 48 dp;
- контраст текста не ниже 4,5:1;
- цвет не является единственным обозначением состояния;
- поддерживаются крупный системный шрифт и экранный диктор;
- технические сведения скрыты за понятным человеческим описанием;
- документация читается как готовая страница, без режима редактирования.

## 1. Главный экран задач

![[assets/Макеты_Тихая_бумага/01_Главный_экран_задач_1080x2400.png]]

Основной смысл: быстро увидеть сегодняшние обязательства, ответственного, срок и состояние. Ожидающее решение выделено мягко, без тревожной перегрузки.

## 2. Агент и подтверждение

![[assets/Макеты_Тихая_бумага/02_Агент_и_подтверждение_1080x2400.png]]

Карточка подтверждения показывает действие и последствия. До нажатия кнопки ничего не изменяется. Пользователь видит, какой контекст доступен агенту.

## 3. Задача и дерево документов

![[assets/Макеты_Тихая_бумага/03_Задача_и_дерево_документов_1080x2400.png]]

Дерево, цепочка навигации и внутренние ссылки дают переходы по материалам задачи. Метка «Только чтение» исключает ложное ожидание прямого редактирования.

## 4. Входящие и производная задача

![[assets/Макеты_Тихая_бумага/04_Входящие_и_производная_задача_1080x2400.png]]

Новая задача от агента показана как предложение. Пользователь может принять, передать или отклонить её. Связь с исходной задачей видна до принятия решения.

## Что уточнить в детерминированном прототипе

- зафиксировать одинаковый порядок нижних вкладок на всех экранах;
- отображать заголовки Markdown без служебных символов разметки;
- проверить перенос длинных названий на реальных размерах экранов;
- проверить крупный шрифт до 200%;
- проверить светлую тему при ярком солнце;
- подготовить состояния без данных, без сети, ошибки и конфликта синхронизации.
