# Priority Decay (Снижение приоритета)

## Определение

Исторический механизм автоматического снижения числового приоритета задачи после переносов. В текущем V21-кандидате выведен из пользовательского интерфейса и бизнес-логики.

## Бизнес-правила

- Перенос сохраняет [[Reschedule_Event|аудит-событие]], но не меняет priority и возвращает `priorityDecayApplied=false`, пока legacy wire-field существует
- Legacy green/red policy objects скрыты, отключены и не имеют продуктового эффекта
- DB/API fields временно сохраняются для production V20 rollback и старых APK
- Удаление legacy fields будет отдельным breaking change после завершения compatibility window

## Пример использования

Исторический пример: повторные переносы могли уменьшать значение 1–10. Это поведение больше не является актуальным контрактом.
