# Wave 1: инфраструктурный фундамент Poruchik

## Итог

**RESOURCE PASS:** после ручного расширения VPS Linux видит достаточный запас для закрытого пилота Poruchik. Подготовлен внутренний контур будущих процессов, а проверка готовности PostgreSQL приведена в соответствие с фактически используемыми функциями. Шлюз Poruchik и серверное ядро задач ещё не запускались и не получали пользовательский трафик.

## Повторный аудит после расширения

| Область | Факт | Оценка |
|---|---:|---|
| Процессор | 4 виртуальных ядра | PASS |
| Оперативная память | 5 509 660 КиБ, то есть около 5,25 ГиБ фактически доступной Linux памяти | PASS |
| Доступная память | 4 209 680 КиБ, около 4,02 ГиБ в итоговом замере | PASS |
| Раздел подкачки | 2 047 МиБ; использовано менее 1 МиБ | PASS |
| Диск | 79 ГиБ всего; 64 ГиБ свободно; занято 15% | PASS |

Тарифное обозначение 6 ГБ и фактический `MemTotal` Linux различаются из-за единиц измерения и системного резерва гипервизора. Фактические 5,25 ГиБ превышают установленный контрольный минимум 3,5 ГиБ.

## Исправление PostgreSQL

PostgreSQL и до изменения принимал соединения, но устаревшая проверка готовности требовала права на четыре функции прежнего планировщика. Эти права не были возвращены: расширять доступ служебной роли ради старой проверки небезопасно.

Вместо этого проверка готовности теперь подтверждает:

- три установленные версии схемы с зафиксированными контрольными суммами;
- функции приёма и завершения обновлений Telegram;
- действующие функции материализации и доставки напоминаний;
- внутреннюю HMAC-проверку системного планировщика;
- актуальную сигнатуру списка напоминаний;
- отсутствие прямого чтения закрытых таблиц служебной ролью.

Кандидат проверки сначала был выполнен отдельно. Затем PostgreSQL был один раз штатно перезапущен, чтобы обновить подключённый только для чтения файл проверки. После запуска PostgreSQL принимает соединения, проверка фундамента завершается успешно, контейнер стабильно имеет состояние `healthy`. Данные и схема не изменялись.

## Подготовленный контур Poruchik

- Создана отдельная сеть Docker `poruchik_internal`.
- Сеть имеет признак `internal=true`, подсеть `/24`, внешнего выхода и опубликованных портов нет.
- В сети пока `0` контейнеров.
- На сервере сохранено проверенное инфраструктурное описание будущих процессов.
- Netdata активна, после загрузки не перезапускалась и автоматически увидит будущие контрольные группы контейнеров.
- Для журналов будущих процессов задано вращение: не более трёх файлов по 10 МиБ.

Установленные бюджеты будущих процессов:

| Процесс | Резерв памяти | Жёсткий предел | Процессор | Предел процессов |
|---|---:|---:|---:|---:|
| Шлюз Poruchik | 64 МиБ | 128 МиБ | 0,25 ядра | 64 |
| Серверное ядро задач | 256 МиБ | 384 МиБ | 0,75 ядра | 192 |

Для обоих процессов зафиксированы: корневая файловая система только для чтения, запрет повышения привилегий и удаление всех системных привилегий. Для Java-ядра максимальная куча ограничена 256 МиБ.

## Сетевая проверка

После подготовки список слушателей не расширился:

- SSH — порт 22;
- HTTPS через Caddy — порт 443;
- n8n — только `127.0.0.1:5678`.

Внутренние службы Poruchik не опубликованы. Таймеры планировщика напоминаний и Netdata активны. Ошибочных служб systemd нет.

## Откат

До запуска приложений полный откат не затрагивает данные:

1. удалить пустую сеть `poruchik_internal`;
2. удалить каталог инфраструктурной заготовки `/opt/poruchik/foundation`;
3. при необходимости вернуть сохранённую предыдущую проверку PostgreSQL и штатно перезапустить только PostgreSQL.

Существующие Telegram, OpenClaw, n8n, Caddy и PostgreSQL не зависят от пустой сети Poruchik.
