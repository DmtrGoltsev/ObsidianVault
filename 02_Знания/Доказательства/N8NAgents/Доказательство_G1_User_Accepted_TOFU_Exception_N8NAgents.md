# G1 — принятое пользователем исключение TOFU

## Что доказывается

Эта заметка доказывает только явное принятие владельцем риска неподтверждённого SSH host key для одного узко ограниченного первого подключения. Она не подтверждает SSH host fingerprint, SSH-порт, подлинность VPS или успешность SSH-подключения.

## Решение пользователя

- Дата фиксации: `2026-08-26`.
- Владелец решения: пользователь `style`.
- Дословное заявление пользователя:

```text
я доверяю ssh и мне не нужен fingerprint    - никто ничего не подменит. можем продолжить работу?
```

## Статус gate

**G1: NOT VERIFIED — USER-ACCEPTED-EXCEPTION (TOFU via accept-new)**

Этот статус никогда не является `PASS`, `MANUAL-PASS` или подтверждением fingerprint. Независимая проверка ожидаемого host fingerprint не выполнена; фактический SSH-порт также не подтверждён и остаётся предположением.

## Точный scope исключения

| Параметр | Разрешённое значение |
|---|---|
| Target | Только VPS по точному IP `154.59.110.121` |
| SSH port | Только предполагаемый `TCP/22`; не подтверждён |
| SSH user | Только `root` |
| Authentication | Только ранее локально проверенный соответствующий private key; без password fallback |
| Host-key policy | Только TOFU с `StrictHostKeyChecking=accept-new` |
| Known hosts | Только отдельный project-scoped `known_hosts`; глобальный файл не изменять |
| Разрешённая операция | Только одна узкая read-only discovery-сессия по перечню мастер-промпта |

Исключение не переносится на другой IP, hostname, SSH user, port, повторно установленный VPS, новый или изменившийся host key и последующие операции вне read-only discovery.

## Явно не разрешено

- Любые mutations на VPS: установка пакетов, запись или удаление файлов, изменение пользователей, SSH, firewall, DNS, Docker, containers, volumes, networks, services, cron/systemd или конфигурации.
- Port scan, перебор портов или подключение к порту, отличному от предполагаемого `TCP/22`.
- Password authentication, запрос или передача password/passphrase в чат, копирование private key либо fallback на иной credential.
- `StrictHostKeyChecking=no`, автоматическое принятие изменившегося ключа, использование или очистка глобального `known_hosts`.
- Подключение к другому host/hostname, redirect/jump host/proxy, NAT endpoint с иным адресом или после reinstall/rekey без нового решения.
- Любое действие, которое создаёт, изменяет или удаляет состояние, даже если оно кажется подготовительным или безопасным.

## Принятый риск

При первом подключении TOFU не доказывает подлинность сервера: атакующий, способный перехватить или перенаправить соединение, может предъявить свой host key, который `accept-new` сохранит как доверенный для последующих подключений. Пользователь явно принимает этот остаточный риск только в указанном scope. Риск не считается устранённым после успешной аутентификации.

## Stop conditions

Немедленно остановиться без обхода, если:

- `154.59.110.121:22` недоступен или подключение требует иной host/port;
- OpenSSH запрашивает password либо key-only authentication не проходит;
- появляется warning об изменившемся host key, несовпадении записи или неоднозначном target;
- project-scoped `known_hosts` нельзя гарантировать;
- требуется `StrictHostKeyChecking=no`, очистка существующего key или иной обход;
- read-only discovery выявляет неизвестную установку, конфликт, нехватку ресурсов или иной stop condition мастер-промпта;
- для продолжения требуется mutation либо расширение scope.

## Rollback

До подключения rollback — отменить попытку. Во время сессии — прекратить команды и закрыть SSH-сеанс. После первого TOFU-подключения — сохранить redacted evidence принятого host key и завершить сессию; при подозрении на подмену не переподключаться. Удаление допускается только для точной записи `154.59.110.121:22` из отдельного project-scoped `known_hosts` после расследования и сохранения evidence; глобальный `known_hosts` не затрагивать.

## Следующий approval gate

Даже успешная read-only discovery не разрешает изменения VPS. Для любых mutations сначала требуются redacted discovery report, архитектура, точный список команд и затрагиваемых объектов, downtime/rollback и отдельный явный approval пользователя.
