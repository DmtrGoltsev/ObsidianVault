# Интеграции OpenClaw

## Telegram

OpenClaw получает сообщения методом долгого опроса: он сам регулярно спрашивает Telegram о новых сообщениях. Поэтому отдельный публичный адрес для OpenClaw не нужен.

Ограничения:

- разрешён один личный чат владельца;
- групповые чаты отключены;
- во время переключения должен работать только один получатель обновлений — OpenClaw или прежний сценарий n8n, но не оба;
- кнопки подтверждения и отмены должны выполняться без передачи решения языковой модели.

## DeepSeek

DeepSeek подключается штатным поставщиком модели OpenClaw. Ключ хранится только на сервере. В модель передаются текст пользователя, необходимая часть контекста и описание разрешённых инструментов.

Модель по умолчанию: `deepseek/deepseek-v4-flash`. Точное имя подтверждается списком моделей установленной версии OpenClaw.

## n8n

OpenClaw обращается к n8n только через закрытый `Action API` — программный интерфейс действий. Запрос содержит:

- название разрешённого действия;
- ограниченный набор параметров;
- доверенный идентификатор пользователя и чата;
- время формирования;
- одноразовый номер;
- ключ защиты от повторного выполнения;
- HMAC-подпись.

n8n повторно проверяет все поля и не доверяет решению OpenClaw автоматически.

## PostgreSQL

OpenClaw не подключается к прикладным таблицам напрямую. Все изменения задач выполняются функциями n8n и PostgreSQL с минимальными правами.

## Будущие собственные инструменты

Каждое новое внешнее API оформляется отдельным именованным инструментом:

1. заранее закреплённый получатель запроса;
2. строгая схема входа и выхода;
3. отдельная привязка учётных данных;
4. ограничения частоты и стоимости;
5. защита от повторов;
6. обезличенный аудит;
7. отдельное подтверждение для рискованных действий.

Модели не предоставляется общий инструмент «выполнить любой HTTP-запрос».
