# Poruchik — стратегическая сессия и решение кворума

## Состав независимых позиций

1. **Бизнес-лидер** — ценность продукта, границы первой версии и измеримый результат.
2. **Ведущий дизайнер** — информационная архитектура, простота и визуальное направление.
3. **Специалист по клиентскому опыту** — путь приглашения, точки доверия, ошибки и восстановление.
4. **Коуч по управлению временем и фокусом** — Фокус, календарь, переносы и защита внимания.
5. **Технический директор** — серверная архитектура, модель данных и границы компонентов.
6. **Лидер тестирования** — сквозные сценарии, конфликты, отказоустойчивость и критерии приёмки.
7. **Специалист по безопасности и приватности** — личные задачи, права, приглашения, подтверждения и аудит.
8. **Android-лид и инженер поставки** — мобильная модульность, автономная работа, push-уведомления и закрытые обновления.

## Общее решение

Все позиции поддержали модель, в которой:

- приложение является центром наблюдаемой работы, а не копией чата;
- существует отдельное серверное ядро задач;
- OpenClaw отвечает за понимание и контекст;
- n8n отвечает за правила и исполнение;
- постоянные входящие важнее push-уведомления;
- задача отделена от технического запуска агента;
- личные задачи сотрудников закрыты от владельца;
- документация читается в приложении, но изменяется только управляемым серверным процессом;
- RocketFlow переносится избирательно.

## Разрешённые разногласия

| Вопрос | Рассмотренные варианты | Решение кворума |
|---|---|---|
| Создавать новое приложение или развивать старое | Полный перенос RocketFlow / новое приложение / гибрид | Новый Android-проект с выборочным переносом после согласования |
| Где хранить состояние задач | В OpenClaw / в n8n / в отдельном ядре | Отдельное серверное ядро задач |
| Может ли приложение обращаться к OpenClaw напрямую | Прямой доступ / серверный шлюз | Только через шлюз приложения |
| Что является источником уведомлений | Push / постоянные входящие | Постоянные входящие; push только сигнал |
| Нужен ли постоянный двусторонний канал | Да / нет | В первой версии нет; push и синхронизация по курсору |
| Где распознавать голос | На телефоне / на сервере | На сервере, чтобы поставщик был заменяемым |
| Можно ли выполнять действия без сети | Все / только безопасные | Только локальные безопасные действия; рискованные требуют связи |
| Может ли агент создавать активные задачи | Автоматически / как предложения | В первой версии только предложения |
| Как распространять приложение | Google Play / закрытый APK / корпоративное управление | Подписанный закрытый APK; корпоративное управление позже |

## Особые замечания ролей

### Бизнес

Главная ценность — превращать просьбу в наблюдаемое обязательство с ответственным, состоянием, доказательством результата и связанной документацией.

### Дизайн и клиентский опыт

Интерфейс должен сохранять простоту RocketFlow, показывать одно главное действие и всегда объяснять следующий шаг при ошибке. Пользователь не обязан понимать внутреннее устройство OpenClaw и n8n.

### Фокус

Фокус — не дополнительный список задач, а ограниченный режим текущей работы. Некритичные уведомления не должны разрушать его.

### Техническая архитектура

Рекомендуется модульное серверное приложение вместо множества преждевременно разделённых служб. Мобильный клиент строится отдельными функциональными модулями.

### Тестирование

Обязательны проверки повторной доставки, конфликта версий, потери push-уведомления, отзыва доступа, просроченного приглашения, отсутствия сети и ошибочного распознавания голоса.

### Безопасность

Роль владельца рабочей области не равна праву читать личные задачи. Любой контекст для OpenClaw формируется сервером после проверки прав.

### Android и поставка

Для автономной очереди используются уникальные идентификаторы операций. Токены хранятся в Android Keystore. APK подписывается постоянным закрытым ключом; Android отклоняет обновление с другой подписью.

## Итоговый статус

Архитектурное и продуктовое предложение Poruchik готово для просмотра владельцем. До ответов на [[07_Открытые_решения_владельца|открытые решения]] реализация не начинается.
