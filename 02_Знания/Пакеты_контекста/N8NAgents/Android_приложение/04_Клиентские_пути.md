# Poruchik — клиентские пути

## 1. Первое приглашение

1. Владелец создаёт приглашение с ролью и сроком действия.
2. Участник открывает ссылку.
3. Если приложение не установлено, открывается закрытая страница установки.
4. После установки та же ссылка завершает вход.
5. Пользователь устанавливает PIN-код или включает биометрию для последующих входов.
6. Повторное использование ссылки запрещено.
7. Пользователь видит только разрешённую рабочую область.

Критическая точка: приглашение не должно открывать чужие задачи даже при пересылке ссылки.

## 2. Привязка Telegram

1. Пользователь входит в приложение.
2. Запрашивает привязку Telegram.
3. Получает короткоживущую ссылку или код.
4. Подтверждает связь в боте.
5. Сервер связывает Telegram с внутренней учётной записью.

Критическая точка: идентификатор Telegram сам по себе не назначает права.

## 3. Личная задача без интернета

1. Пользователь создаёт задачу без связи.
2. Приложение показывает, что изменение ожидает синхронизации.
3. После появления связи операция отправляется с уникальным идентификатором.
4. Задача появляется на сервере ровно один раз.
5. При конфликте пользователь выбирает вариант, а не теряет изменения молча.

## 4. Поручение агенту

1. Пользователь пишет или диктует просьбу.
2. OpenClaw уточняет только недостающие данные.
3. n8n проверяет структуру, права и обязательные правила.
4. Безопасное действие выполняется; рискованное ожидает подтверждения.
5. Результат, доказательства и документация связываются с задачей.
6. Пользователь получает понятный итог, а не технический журнал.

### Голосовой вариант

1. Пользователь записывает голосовую команду.
2. Сервер преобразует запись в текст.
3. Исходная запись удаляется.
4. Пользователь проверяет и подтверждает текст.
5. Только подтверждённый текст сохраняется и передаётся в обычный поток агента.

## 5. Передача части задачи

1. Пользователь выбирает часть работы.
2. Создаётся связанная подзадача.
3. Участнику открываются только эта подзадача и выбранная ветка документов.
4. По умолчанию участник может изменить состояние, задать вопрос и добавить результат.
5. Он не может менять срок, права доступа или передавать задачу дальше без отдельного права.
6. Участник может спросить OpenClaw только об этом контексте.
7. Результат возвращается в исходную задачу.

Критическая точка: личная память владельца и соседние задачи не раскрываются.

## 6. Производная задача от агента

1. Во время работы агент обнаруживает необходимое продолжение.
2. Всегда создаёт предложение, а не активную задачу.
3. Пользователь получает push-уведомление и запись во «Входящих».
4. Можно принять, передать или отклонить предложение.
5. Принятая задача связывается с исходной.
6. Если источника нет, предлагается выбрать цель или временно оставить задачу без классификации.

## 7. Пропущенное уведомление

1. Push-уведомление не пришло или было пропущено.
2. Пользователь позже открывает приложение.
3. Событие остаётся во «Входящих».
4. Переход открывает правильную задачу или карточку подтверждения.

## 8. Чтение документации

1. Пользователь открывает задачу.
2. Переходит во вкладку «Документы».
3. Раскрывает дерево папок.
4. Читает Markdown-страницу.
5. Переходит по внутренней ссылке.
6. Возвращается по цепочке навигации.

Редактирования нет. Просьба изменить документ отправляется агенту и проходит проверяемый процесс n8n.

## 9. Работа в Фокусе

1. Пользователь выбирает ограниченный набор задач на сейчас.
2. Экран скрывает второстепенные списки и уведомления, кроме критичных.
3. Завершённая задача удаляется из Фокуса, но остаётся в истории.
4. Невыполненная задача переносится только явным решением пользователя.
