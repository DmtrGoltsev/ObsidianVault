# Android: фактическая реализация волн 5–10

Дата проверки: 2026-08-31.

Этот документ отделяет уже работающий код от целевой архитектуры. Он не утверждает, что приложение установлено на телефон или прошло проверку с рабочим сервером.

## Основа приложения и защищённое подключение

- Идентификатор приложения: `com.poruchik.app`.
- Минимальная версия Android: API 26; целевая версия: API 34.
- Приглашение открывается глубокой ссылкой `poruchik://invite/v1`.
- Приложение создаёт в Android Keystore (системном защищённом хранилище ключей) неэкспортируемый ключ ECDSA P-256.
- Отпечаток SSH проверяется в каноническом формате OpenSSH. При несовпадении подключение прекращается.
- Используется постоянная учётная запись SSH `poruchik-tunnel` с ограниченными правами.
- Незашифрованный HTTP разрешён только на `127.0.0.1` после поднятия SSH-туннеля. Обращение к внешнему HTTP или HTTPS через программный интерфейс приложения отклоняется.
- Прикладная сессия использует JWT, подписанный ES256. Сетевые ошибки и ошибки проверки ключей закрывают доступ, а не ослабляют защиту.
- Резервное копирование и перенос данных Android отключены: `allowBackup=false`, а правила извлечения исключают всё хранилище приложения.

## Волна 5: оболочка

Реализованы русская навигация и спокойный визуальный стиль «Тихая бумага», состояния загрузки, пустого списка, ошибки и работы без сети. Единственная экспортируемая деятельность приложения — главная точка входа, необходимая для запуска и глубоких ссылок. Служебные компоненты AndroidX либо не экспортируются, либо защищены системными разрешениями.

## Волна 6: работа без сети

- Безопасные изменения попадают в локальную очередь исходящих операций.
- Для повторной отправки используется ключ идемпотентности, поэтому одна операция не должна исполняться дважды.
- Конфликт версий показывается пользователю явно и не перезаписывает серверное состояние молча.
- Рискованные действия, подтверждения и передача задачи другому человеку требуют сети.

## Волна 7: задачи, фокус и календарь

- Есть типизированные хранилища списка и карточки задачи.
- Экран списка показывает статус, принадлежность и состояние синхронизации.
- Карточка задачи показывает доступные детали и переходы.
- Задачу можно добавить в «Фокус» с проверкой версии состояния.
- Календарь собирается из локальной базы и продолжает читаться без сети.

## Волна 8: текст и голос

- Текстовая команда сначала создаётся как черновик.
- Голос распознаётся средствами Android; приложение не сохраняет исходную аудиозапись.
- Перед отправкой пользователь видит распознанный текст и подтверждает его.
- Подтверждённый текст отправляется агенту через типизированный маршрут `POST /v1/agent/commands/text` только при подключении.
- Диалог имеет постоянный локальный идентификатор; сервер получает идентификатор диалога и, если команда дана из карточки, идентификатор задачи.
- Повтор запроса защищён ключом идемпотентности. Команда без задачи разрешена сервером только в общей области диалога и не получает скрытого доступа к чужой задаче.

## Волна 9: уведомления и подтверждения

- Есть локальный центр уведомлений и решений.
- Поддерживаются глубокие ссылки на задачу вида `poruchik://task/<UUID>`.
- Прочтение обычного уведомления можно безопасно поставить в очередь без сети.
- Принятие или отказ от назначенной задачи требуют сети.
- Транспорт уведомлений пока является локальной заглушкой. Firebase Cloud Messaging не подключён: проект Firebase и служебная учётная запись не предоставлены.
- Подтверждение или отклонение рискованной операции отправляется на сервер типизированным запросом. Без сети кнопки возвращают явное сообщение и не создают отложенное рискованное действие.

## Волна 10: документация, передача и приватность

- Реализовано дерево документации только для чтения, переходы по узлам и загрузка содержимого Markdown с сервера.
- Перед сохранением локальной копии приложение проверяет признак «только чтение», тип `text/markdown` и контрольную сумму SHA-256. При несовпадении файл не показывается и не сохраняется.
- Ранее проверенный Markdown можно читать без сети; интерфейс явно помечает сохранённую копию.
- Интерфейс различает личные, командные и доступные по назначению данные.
- Исходящая передача задачи участнику выполняется только при подключении, с проверкой версии задачи и ключом идемпотентности.
- Документы по умолчанию не передаются. Пользователь отдельно включает доступ к корневым документам и отдельно разрешает дальнейшую передачу задачи.

## Что ещё не проверено

- Подпись владельца, установка APK и запуск на реальном телефоне.
- Сквозное приглашение через рабочий сервер и восстановление туннеля после перезапуска телефона.
- Получение данных задач с рабочего сервера.
- Firebase Cloud Messaging и реальные push-уведомления.
- Реальная сквозная проверка команды агенту, подтверждения риска, передачи задачи и чтения Markdown через рабочий SSH-туннель — до установки приложения на телефон.
