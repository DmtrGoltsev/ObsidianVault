# Регламент Деплоя

## Цель

Стандартизировать процедуру развёртывания RocketFlow на production-сервер [[HexCore]].

## Область применения

Деплой backend jar и web статики на HexCore (45.10.110.42). Docker/GHCR deploy не является закрытым production-фактом и остаётся open gate.

## Основной production deploy

Основной путь production deploy для RocketFlow — GitHub Actions workflow `.github/workflows/backend-hexcore-prod-deploy.yml`.

- Auto deploy запускается только при push в ветки, имя которых содержит `release`.
- Workflow дополнительно защищен guard `contains(github.ref_name, 'release')`.
- GitHub environment: `production`.
- Concurrency включен.
- Existing HexCore SSH/SCP/promote/health steps сохраняются.
- `MVP2` больше не является auto-deploy веткой без `release` в имени.
- Required deploy secrets by name: `HEXCORE_PROD_SSH_HOST`, `HEXCORE_PROD_SSH_USER`, `HEXCORE_PROD_SSH_PRIVATE_KEY`, optional `HEXCORE_PROD_SSH_PORT`.

Примечание: эта политика не снимает production BLOCKED/readiness gaps и не подтверждает, что deploy уже выполнен.

## Fallback / alternative deploy

Direct SSH/SCP upload to HexCore остается fallback/alternative способом, когда GitHub Actions недоступен или требуется ручное восстановление. Fallback не должен обходить readiness gates: backup expectation, secrets/env readiness, target ref/method и smoke plan должны быть явно подтверждены.

## Процедура

### Backend (systemd)

1. Собрать backend jar через CI (`backend-verify` workflow)
2. Остановить systemd unit: `sudo systemctl stop rocketflow-backend`
3. Скопировать jar на HexCore
4. Запустить unit: `sudo systemctl start rocketflow-backend`
5. Проверить статус: `sudo systemctl status rocketflow-backend`
6. Smoke check: `curl http://localhost:8080/actuator/health`

### Web (Nginx)

1. Собрать production build: `npm run build` (через `web-verify`)
2. Скопировать статику в Nginx docroot
3. Проверить доступность web через HTTPS

### Откат

- Восстановить предыдущую версию jar и перезапустить systemd unit

## Триггеры запуска

- Ручной: workflow_dispatch (`backend-hexcore-prod-deploy.yml`)
- Автоматический: push только в ветку, имя которой содержит `release`

## Известные blockers/risks

- Production status remains **NOT DEPLOYED / BLOCKED** до отдельного evidence и явного решения пользователя.
- Readiness gaps: target ref/method, backup expectation, secrets/env readiness.
- Docker/GHCR deploy не закрыт и остается open gate.
- Secret values не документируются; допустимы только имена required secrets.

## Критерии успеха

- `/actuator/health` возвращает UP
- Web доступен по HTTPS
- Основные endpoints отвечают 200

## Эскалация

Отказ деплоя → откат → диагностика логов (`journalctl -u rocketflow-backend`) → [[Агент_DevOps]] → [[Оркестратор]].
