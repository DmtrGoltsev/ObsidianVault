# N8NAgents — операционный промпт v1 (2026-08-25)

## Версия и источник

Эта заметка фиксирует безопасную операционную выжимку исходного мастер-промпта с SHA-256 `7b271daf6c3952aff905d2358e2e1a3c36ca789e5be784968311e133d1758da3`. Канонический файл и происхождение: [[Источник_Мастер_Промпт_N8NAgents]].

## Цель

Безопасно развернуть и документировать self-hosted персонального AI-помощника: n8n Community Edition, Docker Compose, Caddy, PostgreSQL, HTTPS editor и отдельный webhook endpoint, Telegram и DeepSeek.

## Обязательная последовательность

1. Local SSH-preflight.
2. Независимая проверка ожидаемого SSH host fingerprint и фактического порта.
3. Только read-only discovery.
4. Проверка актуальной официальной документации и совместимости.
5. Архитектура, threat model, команды, изменяемые файлы и rollback.
6. Явный approval пользователя.
7. Безопасный bootstrap `deploy-n8n`.
8. Phase A MVP, затем проверка; Phase B — только после PASS или согласованного исключения.

## Непереговорные гейты

- До независимого подтверждения фактического порта и ожидаемого host fingerprint SSH запрещён.
- Нельзя использовать автоматическое принятие host key, отключение `StrictHostKeyChecking` или нерасследованную очистку `known_hosts`.
- До discovery, архитектуры и явного approval любые изменения VPS запрещены.
- Не раскрывать private keys и не помещать секреты в vault, Git, вывод команд, workflow exports, screenshots или отчеты.
- Не обходить блокеры отключением TLS, firewall, authentication или иных защит.

## Границы MVP

Phase A включает Compose, PostgreSQL, Caddy/TLS, разделённые editor/webhook domains, Telegram secret verification + allowlist, DeepSeek compatibility spike, память с изоляцией, `tool_search_notes` и `tool_save_note`, базовый backup и проверку persistence.

## Требования к evidence

Использовать статусы `PASS`, `FAIL`, `MANUAL-PASS`, `BLOCKED-EXTERNAL`. Не объявлять success без evidence; не выставлять Final Status `SUCCESS` до подтверждения acceptance criteria исходного промпта.
