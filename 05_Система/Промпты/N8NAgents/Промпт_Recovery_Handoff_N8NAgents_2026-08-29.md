### Фактическая архитектура

- OpenClaw — единственный вход Telegram через долгий опрос и единственный диалоговый контур.
- DeepSeek выполняет языковой вывод; OpenClaw сохраняет Markdown-память и SQLite-сессию. Сохранение после перезапуска проверено.
- Плагин `n8nagents-actions` версии `0.1.2` предоставляет ровно пять инструментов: `reminder_create`, `reminder_list`, `reminder_cancel`, `reminder_reschedule`, `reminder_confirm`.
- Инструменты обращаются к закрытому HMAC Action API n8n: workflow `ActionAPI0000001`, версия `83bd9d8b-278c-4dd1-ad7a-3e7cac9edb69`, путь `/internal/actions/v1`.
- PostgreSQL — источник истины для задач, напоминаний, подтверждений, повторов и аудита.
- Плановые отправки выполняют два свежих n8n workflow: `SchedMatFresh001` версии `2347cf7a-5880-496e-a4c1-3243d641d47c` и `SchedConfFresh01` версии `d0634147-5bf7-49c8-84cc-cd6c910b64f7`.
- Их вызывают активные таймеры `n8nagents-scheduler@materializer.timer` и `n8nagents-scheduler@confirmation.timer` через внутренние HMAC-webhook.
- Caddy возвращает `404` для внутренних Action API и путей планировщиков.
- Прежний основной Telegram workflow n8n и старые планировщики неактивны.

Production PASS: контрольное уведомление доставлено ровно один раз с `message_id=56`; две существовавшие пользовательские задачи не изменились; публичные внутренние пути закрыты; OpenClaw является единственным получателем Telegram.

### Безопасность

- Один разрешённый личный чат, без групп и новых получателей.
- OpenClaw не получает Docker socket, командную строку, браузер, общий доступ к файлам, SQL или произвольный HTTP-инструмент.
- Не читай и не печатай `.env`, токены, ключи, секретные заголовки, идентификаторы пользователя/чата и содержимое сообщений.
- Не допускай одновременной работы двух получателей Telegram.
- При сбое останавливай только проблемный вход или таймер; сохраняй PostgreSQL, задачи и аудит.

### Режим работы

Следуй актуальному `AGENTS.md`: по умолчанию выполняй ясную задачу сам, короткий внутренний план используй для нескольких зависимых шагов, а субагентов — только при конкретной пользе или явной просьбе. Не создавай лишние исследования и не расширяй задачу.

Перед изменением проверь Git-ветку и статус обоих репозиториев. Не трогай чужие изменения. Production-изменения выполняй только в явно разрешённой области и с минимальным откатом.
